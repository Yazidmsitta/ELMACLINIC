# Administration and reports — backend progress

Flutter report domain/API integration is implemented. It preserves signed cash balances in integer centimes, validates the requested calendar range before sending, and rejects mismatched periods, unsupported currencies and inconsistent server totals. Three focused adapter tests cover these behaviors and permission failures. The ADMIN report screen is connected, using the inspected Figma period selector and cards. Today/week/month/year query Casablanca calendar dates through today. Stale responses are discarded, errors never render as zero totals, and pull-to-refresh is supported. Only available financial metrics are shown; trend charts, service breakdowns and accounting profit remain pending.

Migration 023 replaces the original clinic-settings save function with optimistic version checks. GET `/api/v1/clinic-settings` returns `{data, version}` (null data and version 0 before initial setup). PUT requires name, phone, address and the reviewed version, and returns the incremented version. Stale saves return 409 without changing data or audit history. ADMIN enforcement remains in HTTP and SQL. The typed Flutter repository supports this contract; the ADMIN clinic-profile settings screen is connected. Failed saves retain the draft; reloading asks before replacing edits. Only name, phone and address are editable in this increment. Figma Settings.tsx was inspected: the current clinic form implements only its clinic-information subset; the full section menu, account and notification preferences remain pending. Deploy migration 023 and the matching API together.

Migration 022 adds POST `/api/v1/notifications/{id}/read`. Only the active recipient can mark a notification read, including for ADMIN accounts. The server assigns the timestamp; retries retain the first read time. Missing IDs return 404 and another recipient receives 403. Direct authenticated timestamp updates are revoked. Existing GET `/api/v1/notifications` remains recipient-scoped by RLS. Flutter notifications are connected from USER Plus, with pagination, refresh, empty/error states and server-confirmed mark-as-read. The screen reuses existing ElmaClinic cards, typography and icons; no separate notification design was present in the saved Figma source.

Migration 018 adds versioned staff editing. GET `/api/v1/staff` lists protected profiles in pages of 50. PATCH `/api/v1/staff/{id}` accepts full_name, role (ADMIN/USER), active and version. Both HTTP and SQL require active ADMIN access. A change to role or active state revokes sessions. The last active ADMIN cannot be demoted or deactivated. Profiles are retained for historical records. The Flutter staff list and versioned editing screen are connected. Auth account creation remains pending.

Migration 019 adds GET `/api/v1/reports/financial?from=YYYY-MM-DD&to=YYYY-MM-DD`. The inclusive range is limited to 367 calendar days. Receipts use Casablanca day boundaries; expenses use their accounting dates and exclude cancelled entries. All amounts are integer MAD centimes. cash_balance_centimes is recorded receipts minus recorded expenses, **not accounting profit**. Unpaid appointment quotes, taxes, depreciation and inventory valuation are not included. HTTP and SQL both deny USER access.
